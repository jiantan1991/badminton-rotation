# 羽毛球双打轮转系统 · 设计文档

- **日期**：2026-08-07
- **状态**：已确认（用户逐节审核通过）
- **技术形态**：纯静态多文件 Web 应用（无后端、无构建工具、零依赖）

---

## 1. 背景与目标

球友 6 人固定群，线下打羽毛球双打。需要一个"微信打开就能用"的小工具：

1. 输入强组 / 弱组名单（总 6 人，强 2~4 人，弱 4~2 人，主场景 3强3弱）
2. 自动生成 3 场双打对阵表，**每人恰好上场 2 次、休息 1 次**（完美公平）
3. 配队优先"1强1弱 vs 1强1弱"（强带弱、实力接近），允许纯弱/纯强场补齐
4. 打完手动输入比分（如 21:15），系统判胜负
5. 3 场打完自动出积分排名，**一键生成排名图片发微信群**
6. 数据保存在本机（`localStorage`），重新打开页面数据仍在

**角色模型**：单机使用。记录员（通常 1 人）在页面上记分，数据存记录员手机；其他球友线下看同一部手机屏幕，或查看记录员分享到群里的排名图片。**不做**多人实时共享（无服务器，浏览器安全限制）。

## 2. 用户流程

```
① 设置页 ──▶ ② 轮转表页 ──▶ ③ 结果页（排名 + 生成图片）
 输入名单     打一场、记一场     打完 3 场自动进入
```

- **① 设置页**：强组 3 个姓名框 + 弱组 3 个姓名框（可删可加，各 2~4 人，共 6 人）。提示"组内按实力从强到弱填写"。校验通过后点"生成轮转表"。
- **② 轮转表页**：进度（第 2/3 场）、当前场次大字对阵卡、比分输入、下方折叠后续场次预览、底部"查看当前排名"与"提前结束"。
- **③ 结果页**：全部打完自动进入；或手动提前结束。排名榜 + "生成排名图"按钮 + "再来一局"（重输名单）/ "重新轮转"（同名单换顺序）。

## 3. 架构与文件结构

```
badminton-rotation/
├── index.html          # 页面骨架 + 3 个视图容器
```

## 4. 核心算法

### 4.1 场次数与公平性

场数可选 **12 / 15 / 18 / 21 场**（默认 12，2026-08-07 需求扩展：原 3 场）。每场 4 人上场 → N 场共 4N 人次；6 人平分 → **每人恰好 2N/3 场**（12 场每人 8 场、15 场每人 10 场、18 场每人 12 场、21 场每人 14 场），N 被 3 整除时严格公平、无余数。

### 4.2 配队规则（优先序）

1. 每队 2 人，优先 **1强+1弱**（强带弱，两队实力接近）
2. 人数分布导致某场凑不出两队强弱时（2强4弱 / 4强2弱），允许 **2弱 vs 2弱** 或 **2强 vs 2强** 补齐
3. 搭档组合尽量分散（9 种强弱组合使用次数相差 ≤2）
4. 对阵尽量不重复（12 场至少 10 种不同对阵）

### 4.3 生成算法（候选池贪心）

输入：`strong: string[]`（按实力降序）、`weak: string[]`、`numMatches`（默认 12）。
输出：N 场对阵表。

- **候选池**：全部 C(6,4)=15 种人选组合 × 3 种配对 = 45 种对阵（3v3 时过滤为"人选 2强2弱 + 两队各 1强1弱"的 18 种）
- **每轮评分选优**：上场均衡（全局 max-min 差距 ×100，硬性优先）> 对阵未用过（+50）> 搭档组合分散（-2/次）> 强弱搭配偏好（+10，不对称场景）
- **硬约束**：每人上场 ≤ ceil(2N/3)，N 被 3 整除时数学上保证每人恰好 2N/3 场
- 确定性：候选池与枚举顺序固定，同输入同输出；6 人规模毫秒级

### 4.4 积分规则

- 胜一场 +2 分，负 +0 分
- 排名依据（依次）：**总积分 → 净胜分 → 胜场数 → 姓名**（同分比净胜，再同比胜场，再按姓名排序保证稳定）

## 5. 数据模型与持久化

```js
// localStorage key: 'badminton_activity'（集中定义在 storage.js 顶部）
{
  strong: ["张三","李四","王五"],
  weak:   ["赵六","孙七","周八"],
  schedule: [
    { id: 1, teamA: {strong: 0, weak: 0}, teamB: {strong: 1, weak: 1},
      resting: ["王五","周八"], result: null },
    // id 2, 3 同构
  ],
  currentIndex: 0        // 当前进行到第几场（0 基）
}
```

- 提交比分 → `result = { scoreA: 21, scoreB: 15 }` 写入对应场次，**立即保存**
- 每次状态变更（创建活动、提交/修改比分）都写回 `localStorage`
- 排名由 `ranking.js` 基于已打完场次**实时计算**，不存冗余
- "重新轮转"：同名单重新跑算法覆盖 schedule；"再来一局"：清空重建
- 刷新/重开页面：从 `localStorage` 恢复，断点续打

## 6. 分享功能（share.js）

- 结果页"生成排名图"按钮：用 `<canvas>` 绘制排名卡片（背景色 + 排名列表 + 日期 + 冠军标识 🏆）
- 绘制后转 `dataURL` → 页面上显示图片 → 用户**长按图片保存/发送到微信群**
- 移动端适配：Canvas 尺寸按 750px 宽设计（微信图片友好），`devicePixelRatio` 缩放保证清晰
- 备选：同时提供"复制排名文字"按钮（纯文本，无图也能分享）

## 7. 错误处理与边界情况

| 场景 | 处理 |
|------|------|
| 姓名空 / 重复 | 设置页校验，红字提示，阻止生成 |
| 强组或弱组 < 2 人 或总人数 ≠ 6 | 提示当前人数，阻止生成 |
| 比分非数字 / 超出 0~99 | 输入框限制 + 提示 |
| 两队比分相同 | 提示"请输入胜者比分"，不提交 |
| 比分输错 | 已打完场次可点"修改"重输，排名实时重算 |
| 有人早退 | "提前结束"→ 按已打完场次出排名，未打场次忽略 |
| 刷新/重开 | localStorage 恢复现场 |
| 数据损坏（localStorage 被清） | 启动时 JSON 解析失败 → 回到设置页，静默清除坏数据 |

## 8. 测试策略

- **算法单测**（`test.html`，浏览器打开跑断言，绿灯/红灯显示）：
  - 3强3弱：每人恰好 2 场、每场 2 队各 2 人、每队优先 1强1弱、搭档不重复
  - 2强4弱：每人恰好 2 场、含 1 场纯弱场
  - 4强2弱：每人恰好 2 场、含 1 场纯强场
  - 积分：胜 +2、同分按净胜分排序、并列名次稳定
- **手工验收**：真机微信打开 → 完整走一遍 设置 → 3 场记分 → 排名 → 生成图片 → 重新打开恢复现场

## 10. 明确不做（YAGNI）

- ❌ 多人实时数据同步（无后端，浏览器限制）
- ❌ 用户登录 / 权限
- ❌ 历史多场活动存档（每次活动独立，重开即覆盖）
- ❌ 实时计分（只记最终比分）
- ❌ 框架 / 构建工具 / 第三方库
